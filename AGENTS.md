- MCP server lives in src/lib/mcp (one tool per file, OAuth via managed auth, caller-scoped client so RLS applies); routes are generated by mcpPlugin — never hand-edit them. Why: external assistants must act as the signed-in user only.
- Storage reclamation runs through an authenticated server function scoped to the caller's stored objects and the Storage API; privileged reference cleanup preserves diary content even for completed processes. Why: deleting metadata directly leaks physical files and ordinary edit permissions cannot clean archived references.
